## 2. Назначение и цель

1. Периодически измерять температуру 1–4 цифровых датчиков **DS18B20**, подключённых по шине **1-Wire** к одному GPIO.
2. Отображать состояние системы встроенным **адресным RGB-светодиодом** (WS2812): норма / предупреждение / ошибка.
3. Предоставить прикладному коду (`main`) **самодостаточный API**: библиотека сама создаёт и обслуживает шину, находит датчики, опрашивает их с заданным периодом и хранит последние показания.
4. Обеспечить **многократное использование** библиотеки из `main` (`init → start → … → deinit → init`) без утечек ресурсов и без перезапуска МК.
5. Обеспечить **расширяемость**: новые датчики впоследствии сообщают о своих ошибках в общий агрегатор индикации, не изменяя уже написанный код.

## 3. Аппаратная часть

| Компонент | Назначение | Подключение |
|---|---|---|
| ESP32-S3-N16R8 | Основной МК | — |
| DS18B20 (1–4 шт.) | Датчики температуры | DQ → **GPIO 4**, VDD → 3.3 В, GND → общий, подтяжка **4.7 кОм** между DQ и 3.3 В |
| DHT11 (1 шт.) | Температура + влажность | DATA → **GPIO 5**, VCC → 3.3 В, GND → общий, подтяжка **4.7…10 кОм** между DATA и 3.3 В |
| WS2812 (встроенный) | RGB-индикация | **GPIO 48** |

**Ограничения:**
- Максимум датчиков на одной шине: **4** (`DS18B20_MAX_SENSORS`); лишние устройства игнорируются с предупреждением в лог.
- Допустимый диапазон температур: **−55.0 … +125.0 °C**.
- Разрешение датчиков: **12 бит** (время преобразования ≈750 мс; драйвер выдерживает паузу 800 мс).
- Питание датчиков внешнее (3.3 В); режим parasite power не поддерживается.
- Внешняя подтяжка 4.7 кОм обязательна: при её отсутствии в лог выводится предупреждение, индикация красная.

## 4. Архитектура программного обеспечения

### 4.1. Схема зависимостей

```
main
 ├─ ds18b20_sensor ─┬─ indicator ── rgb_led ── espressif__led_strip
 │                  ├─ espressif__ds18b20 ── espressif__onewire_bus
 │                  └─ espressif__onewire_bus
 └─ dht11_sensor ───┬─ indicator ── rgb_led ── espressif__led_strip
                    └─ esp-idf-lib__dht ── esp-idf-lib__esp_idf_lib_helpers
```

### 4.2. Компоненты

| Компонент | Файлы | Назначение | `REQUIRES` |
|---|---|---|---|
| `main` | `main/main.c`, `main/CMakeLists.txt`, `main/idf_component.yml` | точка входа, запуск системы, вывод показаний в консоль | `ds18b20_sensor dht11_sensor` |
| `ds18b20_sensor` | `components/ds18b20_sensor/ds18b20_sensor.c`, `include/ds18b20_sensor.h` | шина 1-Wire, поиск датчиков, периодический опрос, кэш показаний, публикация состояния | `espressif__ds18b20 espressif__onewire_bus indicator` |
| `dht11_sensor` | `components/dht11_sensor/dht11_sensor.c`, `include/dht11_sensor.h` | периодический опрос DHT11 (GPIO5), кэш T/RH, публикация состояния; протокол — `esp-idf-lib__dht` | `esp-idf-lib__dht indicator` |
| `indicator` | `components/indicator/indicator.c`, `include/indicator.h` | агрегатор ошибок/предупреждений от любых источников + задача управления RGB | `rgb_led` |
| `rgb_led` | `components/rgb_led/rgb_led.c`, `include/rgb_led.h` | обёртка над драйвером `led_strip` (один WS2812) | `espressif__led_strip` |

### 4.3. Разделение ответственности

- `ds18b20_sensor` **не управляет светодиодом напрямую** — только вызывает `indicator_report_error()`, `indicator_clear_error()`, `indicator_set_warning()`.
- `indicator` **не знает** о DS18B20, кроме номера источника в перечислении `indicator_source_t`.
- `rgb_led` **не знает** о смысловой нагрузке цветов — только выводит переданный RGB.
- `main` не обращается к шине 1-Wire и к светодиоду напрямую — только через публичный API компонентов.

## 5. Функциональные требования

### 5.1. Компонент `ds18b20_sensor`

| № | Требование |
|---|---|
| F-01 | `ds18b20_sensor_init(gpio_num)` создаёт шину 1-Wire на заданном GPIO через RMT-бэкенд (`onewire_new_bus_rmt`, `max_rx_bytes = 10`). |
| F-02 | После создания шины выполняется пробный `onewire_bus_reset()`; при отсутствии ответа (`ESP_ERR_NOT_FOUND`) в лог выводится предупреждение о необходимости подтяжки 4.7 кОм, инициализация продолжается. |
| F-03 | Выполняется автоматическое перечисление устройств (`onewire_new_device_iter` / `onewire_device_iter_get_next`) и отбор только DS18B20 (`ds18b20_new_device_from_enumeration`); итератор всегда освобождается (`onewire_del_device_iter`). |
| F-04 | Посторонние устройства на шине пропускаются с предупреждением, содержащим их ROM-адрес. |
| F-05 | Число датчиков ограничено `DS18B20_MAX_SENSORS` (4); при превышении — предупреждение и остановка перечисления. |
| F-06 | ROM-адрес каждого найденного датчика выводится в лог в формате `0x%016PRIx64` и доступен программно через `ds18b20_sensor_get_address()`. |
| F-07 | Для каждого датчика устанавливается разрешение **12 бит** (`ds18b20_set_resolution(..., DS18B20_RESOLUTION_12B)`); ошибка установки логируется. |
| F-08 | Если ни один DS18B20 не найден: ресурсы освобождаются, состояние публикуется как ошибка, функция возвращает `ESP_ERR_NOT_FOUND`. |
| F-09 | Повторный вызов `init()` при уже найденных датчиках — no-op (`ESP_OK` + предупреждение в лог); после неудачной попытки (`s_count == 0`) ресурсы освобождаются и поиск выполняется заново. |
| F-10 | `ds18b20_sensor_deinit()` останавливает фоновый опрос кооперативно (см. F-40), удаляет дескрипторы датчиков (`ds18b20_del_device`), освобождает шину (`onewire_bus_del`) и оба мьютекса (показаний и шины); не вызывать одновременно с `read_all()`/геттерами из других задач. После этого `init()` можно вызвать снова. |
| F-11 | `ds18b20_sensor_set_period_ms(period_ms)` задаёт период опроса; значения меньше `DS18B20_PERIOD_MIN_MS` (1000 мс) заменяются на `DS18B20_PERIOD_MS` (1000 мс) с предупреждением. Новый период применяется со следующего цикла, в том числе во время работы задачи. |
| F-12 | `ds18b20_sensor_start()` создаёт фоновую задачу `ds18b20` (приоритет 5, стек 4096 Б); повторный вызов — no-op; при отсутствии датчиков возвращает `ESP_ERR_INVALID_STATE`. |
| F-13 | Периодический опрос выполняется как одно общее преобразование сразу для всех датчиков (`ds18b20_trigger_temperature_conversion_for_all`; пауза 800 мс выполняется внутри драйвера), после чего читается scratchpad каждого датчика (`ds18b20_get_temperature`). |
| F-14 | Период отсчитывается от начала цикла (`xTaskGetTickCount()`): если опрос занял меньше периода, задержка досыпается до `период − elapsed`. Фактический интервал равен заданному периоду, а не «период + время преобразования». |
| F-15 | Признаком ошибки датчика считается: любой ненулевой код ошибки драйвера (`ESP_ERR_INVALID_CRC`, `ESP_ERR_INVALID_STATE` — значение включения питания 85.0 °C, `ESP_FAIL` и др.) **или** температура, равная `DISCONNECT_TEMP` (−196.60 °C) с допуском `DISCONNECT_TOL` (±0.5 °C). Такой датчик получает статус `DS18B20_STATUS_ERROR`, его температура в кэше обнуляется. |
| F-16 | Если температура вне диапазона `DS18B20_TEMP_MIN_VALID … DS18B20_TEMP_MAX_VALID`, датчик получает статус `DS18B20_STATUS_WARNING` (значение сохраняется и доступно через API). |
| F-17 | Итоговый («худший») статус вычисляется по приоритету `ERROR > WARNING > OK`, сохраняется в `s_overall_status` и публикуется в `indicator` функцией `s_publish()`. |
| F-18 | `ds18b20_sensor_read_all(readings)` может вызываться из любого потока: последовательность «convert → чтение scratchpad» сериализована мьютексом шины, кэш — мьютексом показаний (см. F-39); `readings == NULL` допустим — результаты остаются во внутреннем кэше. Возврат: `ESP_OK` — прочитан хотя бы один датчик (в том числе со статусом `WARNING`), `ESP_FAIL` — ни одного, `ESP_ERR_INVALID_STATE` — библиотека не инициализирована. |
| F-19 | Сразу после инициализации статус каждого датчика равен `DS18B20_STATUS_ERROR` («данных ещё нет»), поэтому неработающий опрос не может выглядеть как корректные 0.0 °C. |
| F-20 | `ds18b20_sensor_run(onewire_gpio, rgb_led_gpio)` — единая точка входа: инициализация индикации (не критична: при ошибке работа продолжается без светодиода, её код не попадает в возврат), `init()` датчиков, `start()` опроса. Возвращает `esp_err_t` (`ESP_ERR_NOT_FOUND` — датчиков нет и т.п.); возвращается сразу и не блокирует `main`. |
| F-38 | Новые API: `ds18b20_info_t` (адрес + температура + статус), `ds18b20_sensor_get_info()` — снимок одним захватом мьютекса (согласованные данные), `ds18b20_sensor_set_callback()` — колбэк после каждого цикла чтения (задаётся до `start()`, вызывается вне локов), `ds18b20_status_name()` — текст статуса "OK"/"WARN"/"ERROR". |
| F-39 | Последовательность «convert → чтение scratchpad» в `read_all()` сериализована отдельным мьютексом шины `s_bus_lock`; публикация в indicator и лог идут только при смене состояния (кэш `s_published`, сбрасывается в init/deinit). |
| F-40 | Остановка задачи опроса кооперативная: `deinit()` ставит `s_stop_req`, ждёт самостоятельного выхода до 5 с (пауза между опросами нарезана шагом 50 мс), затем удаляет задачу принудительно; задача удаляет саму себя через `vTaskDelete(NULL)`. |

### 5.2. Компонент `indicator` (агрегатор индикации)

| № | Требование |
|---|---|
| F-21 | Единая точка приёма ошибок/предупреждений от любых источников; источник идентифицируется перечислением `indicator_source_t` (сейчас `INDICATOR_SRC_DS18B20`, новые источники добавляются по мере появления датчиков). |
| F-22 | API: `indicator_init(gpio)`, `indicator_deinit()`, `indicator_report_error(src)`, `indicator_clear_error(src)`, `indicator_set_warning(src, active)`. |
| F-23 | Состояние хранится в битовых масках `s_errors` / `s_warnings` (`uint32_t`, по биту на источник) и защищено критической секцией (`portENTER_CRITICAL` / `portEXIT_CRITICAL`). |
| F-24 | `indicator_init()` идемпотентен: повторный вызов не создаёт вторую задачу и возвращает `ESP_OK`; при ошибке создания задачи светодиод освобождается (`rgb_led_deinit()`). |
| F-25 | `indicator_deinit()` останавливает задачу кооперативно (флаг `s_stop_req`, ожидание до 5 с, затем принудительное удаление), обнуляет маски и освобождает светодиод; после него `init()` можно вызвать снова. |
| F-26 | Задача `indicator` (приоритет 5, стек 3072 Б) обновляет светодиод по текущим маскам (раздел 8). Изменение масок будит задачу через нотификацию FreeRTOS — реакция мгновенная; опрос с периодом `INDICATOR_POLL_MS` (≤ 500 мс) оставлен резервом. Серия красных вспышек прерывается сразу при снятии ошибки; notify выполняется внутри критической секции (задача обнуляет `s_task` под тем же локом). |
| F-27 | В лог пишется только смена отображаемого состояния (норма / предупреждение / ошибка) — без повторов каждые 500 мс. |

### 5.3. Компонент `rgb_led`

| № | Требование |
|---|---|
| F-28 | `rgb_led_init(gpio_num)` создаёт драйвер `led_strip` (RMT, 1 светодиод, разрешение RMT 10 МГц, без DMA) и гасит светодиод; повторный вызов — no-op. |
| F-29 | `rgb_led_set(color)` выводит цвет; если этот цвет уже выведен, обращений к RMT не происходит (кэш последнего цвета). Возвращает `esp_err_t`. |
| F-30 | `rgb_led_off()` гасит светодиод (`led_strip_clear`). |
| F-31 | `rgb_led_deinit()` освобождает драйвер (`led_strip_del`); повторный вызов безопасен. |
| F-32 | Предопределённые цвета: `RGB_COLOR_OFF` (0,0,0), `RGB_COLOR_GREEN` (0,255,0), `RGB_COLOR_YELLOW` (255,255,0), `RGB_COLOR_RED` (255,0,0). |
| F-33 | Результаты всех вызовов `led_strip_*` проверяются; ошибки драйвера возвращаются вызывающему. |

### 5.4. Точка входа `main`

| № | Требование |
|---|---|
| F-34 | `app_main()` задаёт период опроса (`SENSOR_PERIOD_MS` = 1000 мс), регистрирует колбэк `on_readings()`, вызывает `ds18b20_sensor_run(...)` и `dht11_sensor_run(...)` с проверкой возвращаемого `esp_err_t`. |
| F-35 | Если запуск не удался (`err != ESP_OK`, в т.ч. датчиков нет), выводится сообщение об ошибке с указанием GPIO линии DQ и необходимости резистора 4.7 кОм; выполнение продолжается (индикатор мигает красным). |
| F-36 | Показания DS18B20 печатает колбэк `on_readings()` после каждого цикла опроса: индекс, ROM-адрес, температура (°C) и статус (`OK` / `WARN` / `ERROR`). В цикле `main` раз в `IDLE_PERIOD_MS` (1000 мс) дополнительно печатаются `T1` (датчик с индексом 0) и снимок DHT11. Значения берутся из кэша библиотек — шина и датчики при печати не опрашиваются. |
| F-37 | `main` не обращается к шине 1-Wire и светодиоду напрямую — только через публичный API компонентов. |

### 5.5. Компонент `dht11_sensor` (DHT11, GPIO5)

| № | Требование |
|---|---|
| F-41 | `dht11_sensor_init(gpio)` запоминает GPIO и создаёт два мьютекса (кэш показаний + сериализация чтения); **датчик при инициализации не опрашивается** (после подачи питания DHT11у нужно ≈1 с) — наличие проверяет первый цикл, до этого статус `ERROR` («данных ещё нет»). Идемпотентна; `ESP_ERR_NO_MEM` при нехватке памяти. |
| F-42 | Период опроса: `DHT11_PERIOD_MS` = 1000 мс, минимум `DHT11_PERIOD_MIN_MS` = 1000 мс (спецификация DHT11 — не чаще 1 Гц); значение меньше минимума заменяется на 1000 мс с предупреждением. |
| F-43 | Фоновая задача `dht11` (приоритет 5, стек 4096 Б): первое чтение отложено на один период (стабилизация датчика), дальше цикл «чтение → нарезанная пауза (шаг 50 мс)» с периодом от начала цикла. Остановка кооперативная: `deinit()` ждёт до 5 с, затем принудительное удаление; задача удаляет саму себя через `vTaskDelete(NULL)`. |
| F-44 | Чтение: `dht_read_float_data(DHT_TYPE_DHT11, …)` драйвера `esp-idf-lib/dht` под мьютексом `s_read_lock` (≈5 мс, порядок аргументов: влажность, температура). Ошибка/неответ/контрольная сумма → `ERROR` + 0.0/0.0; выход за паспорт (T 0…50 °C, RH 20…80 %) → `WARNING`; иначе `OK`. Кэш обновляется под `s_lock`; публикация в indicator и вызов колбэка — вне локов. |
| F-45 | Публикация в indicator — источник `INDICATOR_SRC_DHT11`; лог и публикация только при смене состояния. До первого успешного чтения — `ERROR` (красный), как у DS18B20. |
| F-46 | API: `init`, `deinit`, `set_period_ms`, `start`, `count` (1 после init / 0 иначе), `read` (живое чтение, ≈5 мс), `get_reading` (снимок из кэша одним локом), `get_temperature`, `get_humidity`, `get_status`, `overall_status`, `set_callback`, `status_name`, `run(dht_gpio, rgb_gpio)` → `esp_err_t` (сбой индикации на возврат не влияет). `read()` возвращает `ESP_OK` даже при `WARNING`. |
| F-47 | `main`: `DHT11_GPIO` = 5, вызов `dht11_sensor_run(5, 48)` с проверкой кода ошибки; раз в секунду из цикла `main` печатается снимок `dht11_sensor_get_reading()` (T, RH, статус), при `count() == 0` строка не печатается. |
| F-48 | Паспортные точности (справочно, для WARNING): T ±2 °C, RH ±5 %; значения вне 0…50 °C / 20…80 % — `WARNING` (жёлтая индикация). |

## 6. Программные интерфейсы (API)

### 6.1. `ds18b20_sensor.h`

```c
#define DS18B20_MAX_SENSORS       4        // максимум датчиков на шине
#define DS18B20_TEMP_MIN_VALID   (-55.0f)  // нижняя граница диапазона, °C
#define DS18B20_TEMP_MAX_VALID   (125.0f)  // верхняя граница диапазона, °C
#define DS18B20_PERIOD_MS         1000     // период опроса по умолчанию, мс
#define DS18B20_PERIOD_MIN_MS     1000     // минимально допустимый период, мс

typedef enum {
    DS18B20_STATUS_OK = 0,   // измерение корректно
    DS18B20_STATUS_WARNING,  // температура вне диапазона
    DS18B20_STATUS_ERROR     // нет ответа / ошибка CRC / нет данных
} ds18b20_status_t;

typedef struct {
    float            temperature;  // последняя прочитанная температура, °C
    ds18b20_status_t status;       // статус последнего чтения
} ds18b20_reading_t;

typedef struct {
    uint64_t         address;       // ROM-адрес датчика
    float            temperature;   // последняя прочитанная температура, °C
    ds18b20_status_t status;        // статус последнего чтения
} ds18b20_info_t;

typedef void (*ds18b20_on_readings_t)(const ds18b20_info_t *infos, int count);

esp_err_t        ds18b20_sensor_init(int gpio_num);
esp_err_t        ds18b20_sensor_deinit(void);

void             ds18b20_sensor_set_callback(ds18b20_on_readings_t callback);

esp_err_t        ds18b20_sensor_run(int onewire_gpio, int rgb_led_gpio);
```

|---|---|

| `get_status(i)` | `DS18B20_STATUS_ERROR` при неверном индексе. |

### 6.4. Пример использования из `main`

```c
#include "ds18b20_sensor.h"
#include "dht11_sensor.h"

#define ONEWIRE_BUS_GPIO 4
#define RGB_LED_GPIO     48
#define DHT11_GPIO       5

static void on_readings(const ds18b20_info_t *infos, int count)
{
    for (int i = 0; i < count; i++)                    // вызывается после каждого цикла опроса
        ESP_LOGI(TAG, "0x%016" PRIx64 ": %.2f C (%s)", infos[i].address,
                 infos[i].temperature, ds18b20_status_name(infos[i].status));
}

void app_main(void)
{
    ds18b20_sensor_set_period_ms(1000);                // опрос 1 раз в секунду
    ds18b20_sensor_set_callback(on_readings);          // вывод показаний — из колбэка

    if (ds18b20_sensor_run(ONEWIRE_BUS_GPIO, RGB_LED_GPIO) != ESP_OK)
        ESP_LOGE(TAG, "DS18B20: запуск не удался");    // esp_err_t, см. F-20

    if (dht11_sensor_run(DHT11_GPIO, RGB_LED_GPIO) != ESP_OK)
        ESP_LOGE(TAG, "DHT11: запуск не удался");      // esp_err_t, см. F-46

    while (1) {
        ds18b20_reading_t ds;
        if (ds18b20_sensor_get_reading(0, &ds) == ESP_OK) { // снимок DS18B20 одним локом
            float t1 = ds.temperature;                     // из кэша, датчик с индексом 0
            // ... расчёт/передача по t1 ...
        }

        dht11_reading_t rh;
        if (dht11_sensor_get_reading(&rh) == ESP_OK)   // снимок DHT11 одним локом
            ESP_LOGI(TAG, "DHT11: %.2f C, %.2f %%", rh.temperature, rh.humidity);

        vTaskDelay(pdMS_TO_TICKS(1000));
    }
}
```

| Функция | Поведение / возврат |
|---|---|

| `set_callback(cb)`, `status_name(s)`, `run(dq, led)` | как у ds18b20 (F-38, F-46): колбэк, текст статуса, `esp_err_t`. |

## 7. Временные характеристики

| Величина | Значение | Где задано |
|---|---|---|
| Период опроса датчиков | 1000 мс по умолчанию, допустимо ≥ 1000 мс | `SENSOR_PERIOD_MS`, `DS18B20_PERIOD_MS` |

| Период вывода показаний | раз в 1000 мс из цикла `main` + колбэк `on_readings` после каждого цикла опроса | `IDLE_PERIOD_MS`, `ds18b20_sensor_set_callback()` |
| Чтение DHT11 (один кадр) | ≈5 мс, блокирует вызывающего | `esp-idf-lib/dht` |

| Реакция индикатора на смену масок | мгновенно (нотификация FreeRTOS); резервный опрос ≤ 500 мс | `INDICATOR_POLL_MS` |
| Красная серия при ошибке | 5 × (100 мс включено + 100 мс выключено) = 1000 мс, затем пауза 1500 мс; полный период 2500 мс | `INDICATOR_BLINK_*` |
| Задержка появления первых данных | ≤ ~810 мс после `start()` | — |

## 8. Логика индикации

| Условие (маски `indicator`) | Цвет WS2812 | Поведение |
|---|---|---|
| `s_errors != 0` (есть ошибка хотя бы одного источника) | **КРАСНЫЙ** | серия из 5 частых вспышек, пауза 1.5 с, повтор |
| `s_errors == 0 && s_warnings != 0` | **ЖЁЛТЫЙ** | горит постоянно |
| `s_errors == 0 && s_warnings == 0` | **ЗЕЛЁНЫЙ** | горит постоянно |

Соответствие состоянию датчиков (публикует `ds18b20_sensor`):

| Состояние датчиков | Публикация в агрегатор | Индикация |
|---|---|---|
| Датчики читаются, все в диапазоне | `clear_error` + `set_warning(false)` | зелёный |
| Есть выход за −55…+125 °C | `clear_error` + `set_warning(true)` | жёлтый |
| Ошибка чтения / CRC / обрыв хотя бы одного датчика | `report_error` + `set_warning(false)` | красный |
| Данных ещё нет (сразу после `init`) | `report_error` | красный до первого успешного чтения |
| Нет датчиков или библиотека остановлена (`deinit`) | `report_error` | красный |

Приоритет состояний: **ERROR > WARNING > OK** (жёлтый не может «перекрыть» красный). DHT11 публикует состояние под источником `INDICATOR_SRC_DHT11`; ошибки и предупреждения обоих датчиков объединяются в общей маске агрегатора — побеждает «худший».

## 9. Обработка ошибок

| Код / признак | Причина | Реакция системы |
|---|---|---|
| `ESP_ERR_NOT_FOUND` | нет ответа шины; ни одного DS18B20 не найдено | предупреждение о подтяжке 4.7 кОм; `init()` возвращает `ESP_ERR_NOT_FOUND`, `count() == 0`, индикатор красный |
| `ESP_ERR_INVALID_CRC` | CRC scratchpad не совпал (наводки, плохой контакт) | датчик → `ERROR`, лог уровня DEBUG с кодом, публикация ошибки в индикатор |
| `ESP_ERR_INVALID_STATE` (от драйвера) | считано значение включения питания 85.0 °C | датчик → `ERROR` (защита от недостоверного значения) |
| `ESP_FAIL` | не удалось создать задачу/драйвер, иные сбои драйвера | `init()`/`start()` возвращают `ESP_FAIL`, сообщение `ESP_LOGE`; состояние индикации остаётся «ошибка» |
| `ESP_ERR_NO_MEM` | не удалось создать мютекс | `init()` возвращает `ESP_ERR_NO_MEM` |
| `ESP_ERR_INVALID_ARG` | неверный индекс датчика или `NULL` в `get_address()` | возврат кода без побочных эффектов |
| −196.60 °C ± 0.5 | обрыв линии DQ / короткое замыкание | датчик → `ERROR`, публикация ошибки |
| Температура < −55.0 °C или > +125.0 °C | выход за паспортный диапазон | датчик → `WARNING`, публикация предупреждения |
| Ошибка `led_strip_*` (RMT) | сбой драйвера светодиода | код возвращается вызывающему; задача индикации продолжает работу |
| Неответ DHT11 / ошибка контрольной суммы | датчик не подключён, нет подтяжки, наводки | `dht11` → `ERROR` (0.0/0.0), публикация `INDICATOR_SRC_DHT11`, DEBUG-лог с кодом |
| `indicator_init()` неуспешен (нет WS2812/сбой) | — | `ds18b20_sensor_run()` продолжает работу **без индикации**, в логе `ESP_LOGE` |

**Правила обработки ошибок:**
- ER-01. Каждая функция, которая может завершиться неуспешно, возвращает `esp_err_t`; результат проверяется везде, где важна диагностика (игнорирование допускается только для «best-effort» операций и помечается приведением `(void)`).
- ER-02. Ошибка инициализации не приводит к зависанию: `ds18b20_sensor_run()` и `dht11_sensor_run()` возвращают `esp_err_t` в `main`, индикатор продолжает показывать ошибку.
- ER-03. Некорректное значение не выдаётся за валидное: при ошибке в кэше хранится `0.0f` и статус `ERROR`.
- ER-04. Все ресурсы, выделенные до момента ошибки, освобождаются (итератор, дескрипторы датчиков, шина, мьютекс, драйвер LED, задача).

## 11. Нефункциональные требования

| № | Требование |
|---|---|
| N-01 | **Потокобезопасность.** Общий кэш показаний и итоговый статус защищены мютексом (`xSemaphoreCreateMutex`); маски агрегатора — критической секцией; геттеры вызываются из любой задачи. |
| N-02 | **Идемпотентность.** Повторный вызов безопасен: `rgb_led_init`, `indicator_init`, `ds18b20_sensor_init`, `ds18b20_sensor_start`, `ds18b20_sensor_run`, все `*_deinit`. |
| N-03 | **Отсутствие утечек.** На всех путях ошибок и при `deinit` освобождаются все выделенные ресурсы. |
| N-04 | **Многократное использование.** Последовательность `init → start → … → deinit → init` работает без перезапуска МК и без «залипших» состояний. |
| N-05 | **Отсутствие «магических чисел».** Все числовые константы — именованные `#define` (раздел 12). |
| N-06 | **Стиль кода.** Блок-комментарий в начале файла с назначением; комментарии логических частей с указанием источника (`[ESP-IDF, esp_log.h]`, `[espressif/ds18b20, ds18b20.h]`, `[FreeRTOS, …]`, `[наш …]`); отступ 4 пробела; открывающая скобка на отдельной строке; статические данные и вспомогательные функции — `static` с префиксом `s_`. |
| N-07 | **Заголовки.** `#pragma once`; обёртка `extern "C"` для совместимости с C++; у каждой публичной функции указаны контракт, параметры и возможные коды возврата. |
| N-08 | **Ресурсы.** Задачи: `ds18b20` — 4096 Б / приоритет 5, `dht11` — 4096 Б / приоритет 5, `indicator` — 3072 Б / приоритет 5. RMT: одна шина 1-Wire (TX+RX) и один канал светодиода; повторных инициализаций не создаётся. DHT11 использует обычный GPIO (RMT не занимает). |
| N-09 | **Отказоустойчивость индикации.** Недоступность светодиода не влияет на измерение температуры. |
| N-10 | **Сборка без предупреждений** при `-Wall -Wextra -Werror`; запрещены неинициализированные/неиспользуемые сущности. |
| N-11 | **Отсутствие блокировок в `main`.** Точка входа не выполняет длительных операций ожидания преобразования (800 мс) — это делает фоновая задача. |

## 15. Ограничения реализации и направления развития

**Ограничения:**
1. Максимум **4** датчика на шине (`DS18B20_MAX_SENSORS`); добавление датчика «на горячую» после инициализации не отслеживается — требуется `deinit()` + `init()`.
2. Одновременно поддерживается **одна** шина 1-Wire: состояние библиотеки хранится в статических переменных (нельзя создать два независимых экземпляра).
3. Передача данных наружу (Wi-Fi / MQTT / запись в файл) не реализована: показания доступны через API и в консоли.
4. Питание датчиков только внешнее (3.3 В); режим parasite power не поддерживается.
5. Параметры задаются макросами в коде; Kconfig (`menuconfig`) не используется.
6. Требуется внешний резистор подтяжки 4.7 кОм; при его отсутствии система работоспособна только в части индикации ошибки.

**Направления развития:**
1. Новые датчики (BME280, SHT31, …) реализуются отдельными компонентами с регистрацией собственного значения в `indicator_source_t` — существующий код при этом не меняется.
2. Вынос настраиваемых параметров в `Kconfig.projbuild` и/или в NVS.
3. Поддержка нескольких экземпляров библиотеки (передача контекста-структуры вместо статических переменных).
4. Периодический перепоиск датчиков (hot-plug) и восстановление после длительного отсутствия связи.
5. Хранение последних показаний в NVS/RTC для передачи после перезапуска; вывод через MQTT/HTTP.
